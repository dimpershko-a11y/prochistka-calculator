## 2. Обязательные новые unit-тесты ядра
- Q01: нулевая, отрицательная, дробная, минимальная и очень большая площадь; `NaN`, `Infinity`; сохранение запрещено при неконечных суммах.
- Q02: базовая ставка × площадь, коэффициенты заставленности/загрязнения, порядок округления.
- Q03: минимальная цена для генеральной/после ремонта/поддерживающей при малой площади; допуслуги с флагом `countsTowardMinimum`.
- Q04: допуслуги 0/1/дробное количество, отрицательная цена, пустая единица измерения и удалённая услуга.
- Q05: выезд за КАД внутри/вне включённых километров, переключение типа.
- Q06: скидка 0/обычная/100/более 100%; отдельно тест коммерческого минимума **после утверждения правила**.
- Q07: налоги, материалы, зарплата, полная себестоимость и прибыль, соответствие строк итоговой сумме.
- Q08: абонемент поддерживающей уборки (2/4/8 уборок в месяц, 3/6/12 месяцев), число визитов, скидка, цена одного визита, общий итог.
- Q09: без выбранных услуг, только допуслуги, запрещённые отдельно позиции.
- Q10: изменение тарифа между сохранением и просмотром заказа; `quoteSnapshot` не меняется.

## 4. Генератор договора — обязательные 12 тестов
| № | Сценарий | Ожидаемый результат |
|---|---|---|
| C01 | Заказ с одной базовой уборкой | Тип, адрес, перечень работ и сумма подставляются из `quoteSnapshot` |
| C02 | Уборка + 3 допуслуги | Только выбранные услуги, корректные `qty×unitPrice`, единицы измерения и общая сумма |
| C03 | Вручную поменять ФИО/телефон | В документе новые поля; исходный заказ неизменён |
| C04 | Поменять дату/время | Новые значения в черновике и PDF |
| C05 | Удалить/добавить пункт работ | Сохраняется порядок и комментарий о ручной правке |
| C06 | Закрыть редактор и снова открыть | Черновик и версия шаблона сохранены |
| C07 | Очень длинная услуга и описание | Нет наложений, текст переносится |
| C08 | Документ 1/3/8 страниц | Настоящие страницы A4, адекватные разрывы, подписи не разорваны |
| C09 | Русские символы, №, ₽, длинный адрес | Корректные шрифты в превью, PDF, печати |
| C10 | Создание договора со смартфона | Редактор, предпросмотр и PDF доступны, нет горизонтального скролла |
| C11 | Изменить цену позиции | Новый итог рассчитан, старая цена и разница видны; PDF только после подтверждения |
| C12 | Открыть старый заказ после изменения тарифов | Старая согласованная сумма и работы не меняются, нет подстановки новых описаний без согласия |

## 4.1. Дополнительные тесты по согласованным условиям
- C13: Общий шаблон + пример B2B: выбранный тип заказчика включает нужный набор реквизитов; юридический текст не изменяется без утверждения; клиентские реквизиты не попадают в public config.js.
- C14: Фирменная шапка из образца сохраняется **на первой странице каждого самостоятельного документа**: договор B2C/B2B, смета/КП, приложение, акт; проверять в предпросмотре, печати и PDF.
- C15: Для A4 длиной 1/3/8 страниц первая страница каждого самостоятельного документа имеет шапку, последующие — без неё, как в исходниках; нижний колонтитул пуст, автоматической нумерации нет. Шапка не перекрывает содержание. Размещение шапки на каждой странице запрещено утверждённым требованием; в пакетном PDF отдельно проверить первую страницу договора и первую страницу самостоятельного акта.
- C16: Стартовое время `form.cleanStartTime` (HH:MM) переносится из калькулятора в сохранённый заказ, `quoteSnapshot`, черновик и печатный договор; старые заказы без времени открываются без ошибки.
- C17: Разница между суммой договора и заказа требует обязательного комментария и явного подтверждения; согласованная цена и исходный заказ сохраняются.
- C18: Получены три пары DOCX/PDF: общий образец на 4 страницах и два B2B на 3 страницах каждый. После реализации сравнить фирменный блок, шрифты, таблицы, состав акта и переносы с реальными эталонами; результат «совпадает» не отмечать до проверки.
