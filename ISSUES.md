## Карточки

### P01. Неконечные значения расчёта
- **Доказательство:** тест отдельной копии `production`: `area=1e308` приводит к `recommendedPrice=Infinity`, сериализация JSON даёт `null`, а `validateOrder` возвращает 0 ошибок. `num` отсеивает отрицательные, но пропускает бесконечность/переполнение.
- **Влияние:** сохранение/печать некорректных сумм и расхождение данных заказа.
- **Исправление:** ограничить диапазон вводимых чисел, проверить `Number.isFinite` в общей валидации и перед сохранением/PDF. Не изменять тарифы.
- **Риск изменения:** низкий/средний. **Проверка:** 0, -1, дробное, MAX допустимое, сверх MAX, 1e308, NaN, Infinity.

### P02. Слабая валидация backup
- **Доказательство:** `CORE.validateBackup({type:'prochistka_full_backup',state:{form:{area:NaN,cleanType:'no-such'},extras:[],savedOrders:[]}})` возвращает `ok:true`.
- **Влияние:** повреждённые локальные настройки/заказы после импорта.
- **Исправление:** схема документа с версией; проверка типов и допустимых диапазонов; частичный импорт с отчётом об ошибках, атомарное применение после ручного подтверждения.
- **Риск:** средний. **Проверка:** старые и новые версии backup, битый JSON, неверный тип услуг, пустые обязательные поля.

### P03. Неизменность старых заказов и явность повторения
- **Доказательство:** браузерный сценарий сохранил старые 17 010 ₽; повышение тарифа + `repeatSavedOrder()` дало 23 814 ₽, при этом старые 17 010 ₽ остались в `savedOrders`. Код повторения восстанавливает `form`, количества услуг, затем вызывает `calc()` по текущему `state.cleaningTypes`.
- **Влияние:** пользователь может принять новую цену за ранее согласованную; риск неверного договора.
- **Исправление:** разделить «Просмотреть сохранённый расчёт/документ» и «Создать новый заказ по текущим тарифам»; сохранять `quoteSnapshot` с версиями тарифов и полным составом работ.
- **Риск:** средний. **Проверка:** создать заказ, поменять тариф, открыть старый документ и отдельно повторить.

### P04. Устаревшие E2E-ожидания
- **Доказательство:** фактический `node tests/e2e.js` (Chrome) дал FAIL для сравнения собственного снимка, трёх проверок устаревшей модели «серии» и автоматического поднятия цены. Затем Playwright `page.check('#forceDiscount')` завершился 30-секундным таймаутом — соответствующий элемент отсутствует. В актуальном `CORE.calculateOrder()` поля серии являются совместимыми заполнителями для старого UI, основной механизм абонемента — `maintenanceFormat='subscription'`.
- **Влияние:** зелёная/красная регрессия недостоверна, новые изменения рискованны.
- **Исправление:** обновить сценарии на реальные абонементы и текущую политику цены; убрать селекторы удалённых функций; отделить сетевые тесты от локальных.
- **Риск:** низкий. **Проверка:** полный E2E должен завершаться без таймаута и без заведомо устаревших ожиданий.

### P05. Lint
- **Доказательство:** `npm run lint` остановился на двух ошибках ESLint: `helpers.js:185 preserve-caught-error` и `helpers.js:389 no-useless-assignment`. Этапы CSS/HTML не исполнялись.
- **Исправление:** небольшая правка двух мест, затем повтор JS/CSS/HTML lint.
- **Риск:** низкий. **Проверка:** 0 ошибок по всем линтерам.

### P06. Зеркалирование старой ветки Apps Script
- **Доказательство из кода:** `getSettings_().pagesBranch` по умолчанию `work-v4.10.1`, `doPost` сначала выполняет PUT в `production`, потом отдельно в `pagesBranch`, а исключение второго PUT попадает в общий `catch`. Эта старая ветка реально содержит историческую ревизию.
- **Влияние:** ложная ошибка «не опубликовано» при успешной записи основного `production`.
- **Исправление:** `GITHUB_PAGES_BRANCH=production` или отказаться от зеркала; фиксировать основной commit до вторичного действия, возвращать частичный статус, не повторять публикацию без проверки контента.
- **Риск:** средний. **Проверка:** замокировать вторичный PUT как ошибочный, проверить ответ `published:true, mirror_failed:true`, без повторной основной записи. Активные Script Properties пока не проверены.

### P07. Проверка только ревизии
- **Доказательство:** `verifyPublishedConfigRevision` принимает любую `CONFIG_REVISION >= expected`, не сравнивая ожидаемую конфигурацию и автора.
- **Влияние:** при параллельной публикации можно ошибочно подтвердить чужое изменение.
- **Исправление:** проверять хэш/контент подготовленного `configText` или записанный commit SHA, обеспечить уникальный id запроса и неизменность ревизии.
- **Риск:** средний. **Проверка:** две конкурирующие записи и устаревший raw CDN.

### P08. Недостаточная гарантия сохранения данных
- **Доказательство:** `saveState()` перехватывает ошибки `localStorage.setItem` без уведомления; `idbSave()` также проглатывает ошибки. IndexedDB расположен в том же origin/профиле.
- **Влияние:** пользователь думает, что заказ сохранён, хотя квота/приватный режим могли сорвать запись.
- **Исправление:** явный статус сохранения и реакция на отказ, периодическая скачиваемая копия, версия модели и проверка восстановления.
- **Риск:** средний. **Проверка:** quota exceeded, закрытая IndexedDB, очистка storage, импорт старого backup.

### P09. Мобильная ширина
- **Доказательство:** Chrome smoke, `document.documentElement.scrollWidth/window.innerWidth`: 323/320 и 482/430; другие проверенные размеры 375,390,768,1280 без превышения. Источник не локализован, возможна особенность скрытых/трансформированных элементов.
- **Влияние:** потенциальный горизонтальный скролл и доступность кнопок.
- **Исправление:** проверить видимую область, контейнеры и fixed/absolute элементы скриншотами; CSS точечно после подтверждения.
- **Риск:** низкий. **Проверка:** ширины 320,360,375,390,414,430,768; разные состояния модалок.

### P10. Формат PDF
- **Доказательство:** `generatePdfBlob` задаёт jsPDF `format:[210,pageHeightMm]`, где `pageHeightMm` — высота всего документа. Это **одна длинная страница**.
- **Влияние:** договор с несколькими страницами будет неудобен для печати и подписания, невозможно корректно закрепить нумерацию страниц.
- **Исправление:** отдельный многостраничный экспорт A4 для договора; текущую смету оставить без регресса.
- **Риск:** средний. **Проверка:** 1,3,8 страниц, кириллица, подписи и таблицы на разрывах.

### P11. Клиентская парольная защита
- **Доказательство:** `APP_PASSWORD` находится в загружаемом браузером `config.js`; на проверенной ревизии пуст. Это не защита от человека, который может изменить собственную копию JS и localStorage.
- **Влияние:** иллюзия доступа по ролям; нельзя хранить там реквизиты секрета или личные данные.
- **Исправление:** использовать только как UI-блокировку; реальную авторизацию ставить на сервере/доверенном API, не объявлять локальный пароль полноценной безопасностью.
- **Риск:** низкий для документации, высокий для смены архитектуры.

### P12. Минимум и скидка — не утверждённое бизнес-правило
- **Доказательство:** при 70 м² и скидке 100% тест даёт 0 ₽ при минимальном базовом тарифе 12 000 ₽: скидка применяется после минимальной стоимости, `Math.min(100,discount)`.
- **Влияние:** ошибка оператора может дать нулевую цену.
- **Исправление:** после согласования бизнес-правила предупреждение, ограничение или отдельное подтверждение сверхлимитной скидки. **Не считать багом без решения владельца.**
- **Риск:** средний для поведения коммерческой цены.
