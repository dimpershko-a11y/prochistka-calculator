# DOCUMENT_TEMPLATE_MAPPING.md — карта исходных договоров и колонтитулов

Дата анализа: 14.10.2026. **Источник: реально полученные пользователем DOCX и PDF**. Этот документ содержит только схему/оформление. Оригиналы и данные конкретных заказчиков **не загружать в публичный GitHub**.

## 1. Какие источники сверены
- `Договор клининг 2026 v4(1).docx` — общий редактируемый шаблон; `Договор клининг печатный(1).pdf` — его печатный эталон, 4 страницы A4.
- `Договор клининг ГЗ Новосибирск(1).docx` — заполненный B2B-договор; `Договор ГЗ Новосибирск(1).pdf` — печатный эталон, 3 страницы A4.
- `Договор клининг Фонд СВР.docx` — второй заполненный B2B-договор; `Договор клининг Фонд СВР.pdf` — печатный эталон, 3 страницы A4.

Сравнены структура OOXML и PDF-отображение: одна секция в каждом DOCX; `different_first_page_header_footer=true`, первая шапка находится в `first_page_header`; `header` для последующих страниц пуст; `footer` пуст. Визуальный PDF подтверждает, что фирменный блок есть **только на первой странице документа**. Нумерации страниц и подписанного нижнего колонтитула в образцах нет.

## 2. Эталон внешнего вида — зафиксировать
| Элемент | Фактически обнаружено | Требование генератору |
|---|---|---|
| Формат | A4 портрет, 21.0×29.7 см, верх/низ 1.27 см | Сохранить базовый формат и поля или явно отметить невозможность |
| Шапка (1-я страница) | Таблица из 2 ячеек без растровых логотипов | Воссоздать средствами HTML/CSS/DOCX/PDF, не вставлять случайный логотип |
| Левая часть | `PRO-CHISTKA` — **Orbitron Black, 24 pt**; под ним «клининговые услуги» — 12 pt с визуальной разрядкой | Использовать локальный Orbitron начертания 900; сохранить визуальную разрядку |
| Правая часть | Телефон, email, сайт — Arial, **10 pt, жирный**, выравнивание по правому краю | Брать контакты из настроек бренда, версионировать с документом |
| Разделитель | Тонкая горизонтальная линия под фирменной шапкой | Сохранить линию и её интервалы |
| Остальные страницы | Фирменный блок в PDF **не повторяется** | Не заявлять, будто он повторяется: базовый режим `headerMode:'first-page'` по оригиналу; опция повторения — только после отдельного подтверждения |
| Нижний колонтитул | Пуст; автоматического номера страницы нет | По умолчанию ничего не придумывать, включая «Страница X из Y» |
| Тело | В основном Arial, около 9 pt; заголовок договора Arial 12 pt жирный | Сохранять читабельность; полные визуальные сравнения при внедрении |
| Подписи | Двухколоночная таблица: «Исполнитель» / «Заказчик» | Разделять реквизиты и подписи по типу заказчика |

**Правило владельца «сохранить колонтитул для всех документов»**: каждый отдельно сформированный документ (договор B2C, договор B2B, смета, акт, приложение, КП) имеет **ту же фирменную шапку на своей первой странице**. При объединении документов в один PDF необходимо технически обеспечить шапку в начале каждого самостоятельного документа (например, через отдельную секцию / отдельный PDF и сборку), иначе приложение на 4-й странице общего договора останется без фирменной шапки, как в существующем печатном эталоне.

Наличие верхней шапки **на каждой странице**, а не только в начале документа, отдельно не утверждено. Не менять исходный факт молча.

## 3. Общая структура договора
1. Заголовок «Договор на оказание клининговых услуг», номер, город и дата.
2. Преамбула: заказчик и исполнитель (ИП).
3. Раздел 1 «Предмет договора»: объект, площадь, адрес; вариант уборки, состав работ; дополнительные услуги и согласование.
4. Раздел 2 «Права и обязанности сторон»: обязанности исполнителя и заказчика.
5. Раздел 3 «Оплата и приемка услуг»: цена, изменение цены, согласование дополнительных работ, акт, замечания, сроки оплаты, ответственность за просрочку и форс-мажорные обстоятельства.
6. Раздел 4 «Ответственность сторон»: ущерб и исключения.
7. Реквизиты сторон с разными таблицами для физических и юридических лиц.
8. **Общий шаблон содержит «Приложение № 1 — Акт оказанных услуг» отдельной 4-й страницей.** Для генератора это отдельная связанная сущность `ActDraft`; как минимум доступна при подготовке договора, а экспорт в отдельный PDF — предусмотренный сценарий.

**Юридическую редакцию каждого пункта сохранить из исходника без самовольного исправления.** Перед выпуском юридический текст, в частности ограничения ответственности, сроки приёмки/оплаты и НДС, согласовать с юристом/бухгалтером.

## 4. Варианты B2C и B2B
- Общий пустой шаблон: выбор вида уборки («Поддерживающая», «Генеральная», «После ремонта», «Мытье окон»); свободные строки дополнительных работ; поля физлица (ФИО, регистрация, паспортные реквизиты и телефон в одном из образцов).
- Заполненные B2B: вместо галочек — конкретный вид уборки и фактический список операций; реквизиты организации и представителя; различается детальность описания работ и состав реквизитов.
- Статический текст об оплате в шаблоне использует разные сроки для физлица и юрлица. Сохранять, пока юридическая редакция не согласована отдельно; не создавать два конкурирующих набора пунктов на основе предположений.
- В заполненных B2B PDF встречается расширенная формулировка о применении УСН и отсутствии НДС со ссылкой на НК РФ, в общем шаблоне — краткое «без НДС». **Не подставлять всем заказам налоговый статус автоматически** без проверки текущего режима исполнителя и согласования юридического текста; это переменная редакция пункта 3.2.
- Не переносить конкретные реквизиты юридических лиц из примеров в дефолтные поля шаблонов. Данные реальных заказчиков остаются в локальных сохранённых заказах/черновиках.

## 5. Карта автозаполнения
| Фрагмент исходного договора | Поле заказа/черновика | Источник / правило |
|---|---|---|
| Номер, дата, город | `contractDraft.documentNo/documentDate/city` | Ручная корректировка; номер не должен дублироваться на устройствах |
| Исполнитель | `contractor.*` | Утверждённые реквизиты ИП, отдельно от контактов рекламного бренда |
| ФИО или организация заказчика | `customer.type/name` | Физлицо / юрлицо из формы договора |
| Представитель / основание полномочий | `customer.representative/basis` | Только B2B; если исходник не содержит — пустые до подтверждения |
| Объект, площадь, адрес | `quoteSnapshot.object.*` | Из сохранённого заказа, без тихой подмены |
| Дата уборки | `form.cleanDate` | Уже есть в калькуляторе |
| Время начала | `form.cleanStartTime` | Новое поле калькулятора, формат HH:MM |
| Вид и список работ | `quoteSnapshot.service/items` | Фиксировать на дату согласования, не брать из нового config при открытии старого заказа |
| Допработы | `contractDraft.extraWorks` | По заказу + отдельные ручные правки без изменения исходной сметы |
| Сумма и НДС | `quoteSnapshot.pricing.total` + `contractDraft.taxClauseVersion` | Из сохранённого заказа; отдельная юридически проверенная редакция налоговой фразы |
| Контакты в шапке | `branding.headerSnapshot` | Единая фирменная шапка; по умолчанию в начале каждого документа |
| Реквизиты и подписи | `contractDraft.parties` | Разные таблицы B2C/B2B, обязательная проверка перед PDF |
| Акт (приложение № 1) | `ActDraft` и `contractId` | Договорный номер и дата, стороны, результат, замечания, подписи |

## 6. Критерии качества и вопросы
- Эталонная проверка **общий шаблон 4 страницы** и **два B2B-образца по 3 страницы**: содержимое, переносы, фирменная шапка, таблица подписей. У генерируемых договоров число страниц может отличаться из-за динамического списка работ, но не должно быть обрезаний.
- Обязательно проверить тестовые документы на 1/3/8 страницах, с длинными текстами/реквизитами и кириллицей.
- Применить оформление к **смете**, сохранив исходные параметры `state.pdfHeader`; внедрять в действующий экспорт только после сравнения и согласования.
- **Нужно подтвердить один вопрос:** должен ли брендовый верхний колонтитул повторяться **на каждой странице** или, как в оригинале, **только на первой странице каждого самостоятельного документа**? До ответа базовый режим — сохранение поведения оригинала.
- Юридические и налоговые формулировки (включая ссылку на НК РФ и сроки) требуют отдельной проверки, не корректировать без решения владельца.
